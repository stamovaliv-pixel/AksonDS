# Doxi 2.0.1 — анализ вложений CSV / XLS / XLSX

## Назначение

Этот патч добавляет в установленную Doxi 2.0 передачу файла вместе с обычным сообщением и анализ табличного содержимого локальной моделью Qwen через уже настроенный защищённый туннель.

Поддерживаются:
- CSV: UTF-8, UTF-8 BOM, UTF-16 LE/BE и Windows-1251; автоматическое определение `;`, `,`, табуляции и `|`; корректная обработка кавычек и разделителей внутри кавычек.
- XLS и XLSX: чтение листов, названий листов, строк и значений с помощью закреплённой версии SheetJS 0.20.3.
- Для книг Excel анализируются максимум 8 листов; до 1 500 строк и 80 столбцов на лист; общий предел 150 000 ячеек; для CSV принимается до 25 000 строк; текст, передаваемый модели, ограничен 7 600 символами. Для многолистовых книг выборка распределяется между листами, чтобы первый лист не вытеснил остальные. Ограничение явно сообщается Докси.
- Максимальный размер файла — 10 МБ. Для XLSX дополнительно проверяется ZIP-каталог и общий распакованный размер до 40 МБ.

## Безопасность и конфиденциальность

1. Файл передаётся из браузера в Edge Function Supabase как multipart/form-data. Поэтому Supabase принимает и временно обрабатывает байты файла в памяти функции.
2. Edge Function читает CSV/XLS/XLSX в памяти и передаёт извлечённые табличные значения только в локальную Qwen через уже используемый `DOXI_TUNNEL_URL`.
3. Файл не загружается в Supabase Storage и не сохраняется в новой таблице. После завершения запроса содержимое не сохраняется функцией. В историю Докси записывается только текст вопроса и метка `[Вложение: имя_файла]`; извлечённые строки не записываются в историю.
4. Запрос и содержимое файла не отправляются в Brave Search, OpenAI или другой внешний AI API.
5. SheetJS подключён как зафиксированная версия 0.20.3 с официального CDN `cdn.sheetjs.com`. Это внешний источник кода библиотеки; байты пользовательского файла в CDN не передаются. SheetJS помечает поддержку Deno как экспериментальную, поэтому после публикации необходим тест в Supabase Edge Runtime. Для полностью автономной поставки библиотеку можно отдельно vendoring-нуть в репозиторий.
6. Текст ячеек рассматривается как недоверенные данные, а не инструкции. Формулы не исполняются и не пересчитываются; используются только доступные сохранённые значения.
7. Действующие ролевые проверки Doxi 2.0 и серверные обработчики бронирования остаются перед анализом вложения. Если сообщение — команда создания/изменения/удаления записи, сначала отрабатывает существующая логика действий. При создании записи ранее выбранный файл можно загрузить как реестр только после отдельного подтверждения, как и раньше.

## Установка

1. Сделайте резервную копию текущих файлов `supabase/functions/doxi-chat/index.ts`, `js/ai-ds.js` и 14 HTML-файлов из `app/`.
2. Скопируйте содержимое папки `DOXI_2_0_1_ATTACHMENT_ANALYSIS_PATCH/` в корень проекта с сохранением путей.
3. Опубликуйте Edge Function:

   ```powershell
   supabase functions deploy doxi-chat
   ```

4. Опубликуйте frontend как обычно. HTML-файлы в архиве обновляют cache-busting-параметр общего `ai-ds.js`.
5. SQL, таблицы, RLS, Storage policies, роли, секреты и настройки Supabase менять не нужно.

## Проверка

1. В чате Докси прикрепите `sample_attachment_analysis.csv` и напишите «Проанализируй вложенный файл».
2. Повторите с `sample_attachment_analysis.xlsx` — в ответе должны быть два листа.
3. Попробуйте CSV с разделителем `;` и Windows-1251 (если используете соответствующий пример).
4. Прикрепите файл и задайте вопрос без текста — Докси должна использовать стандартный запрос анализа.
5. Проверьте файл более 10 МБ — сервер должен отказать с понятным сообщением.
6. Отправьте сообщение «Создай запись слота ...» с прикреплённым файлом — обычный сценарий создания/подтверждения должен остаться штатным; файл может прикрепиться к записи только после подтверждения.
7. Отправьте «Прикрепи этот реестр к последней созданной записи» при наличии такой записи — должен отработать существующий `upload_registry`.

## Границы проверки

Патч прошёл локальные статические проверки JavaScript/TypeScript, проверку CSV-кодировок/разделителей и ZIP-каталога тестового XLSX. Проверка живой Supabase Edge Function, сетевой загрузки SheetJS в инфраструктуре Supabase, фактического чтения XLS/XLSX библиотекой в Edge Runtime и end-to-end анализа в Ollama возможна только после развёртывания в вашем проекте. Никакие изменения production не выполнялись.
