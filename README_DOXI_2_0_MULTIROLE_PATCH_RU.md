# Doxi 2.0 — multi-role patch

## Что входит в патч

1. `supabase/functions/doxi-chat/index.ts` — серверная логика Doxi:
   - доступ к чату управляется `doxi_settings.allowed_roles`;
   - `super_admin` остаётся обязательной ролью;
   - настройки `notes_enabled` и `reminders_enabled` читаются, возвращаются в настройках, сохраняются из панели управления и реально проверяются при командах;
   - загрузка реестра повторно проверяет глобальное включение Doxi и разрешение текущей роли;
   - ответы Докси приведены к обращению на «вы»;
   - серверная проверка JWT, роли, владения данными и подтверждений действий сохранена.
2. `js/ai-ds.js` — общий виджет: вежливое приветствие и обращение на «вы».
3. `js/ai-ds-management.js` и `app/ai_ds_management.html` — управление доступом по ролям и переключатели заметок/напоминаний.
4. Остальные HTML-файлы из `app/` — только обновление cache-busting версии общего `ai-ds.js`, чтобы браузер не продолжил загружать старый скрипт.
5. `diagnostics/READ_ONLY_check_doxi_commit_booking_action.sql` — необязательная диагностическая SQL-проверка функции. Запрос только читает определение функции.

## Важные границы доступа

- Панель управления Докси, глобальные настройки, общая история диалогов и управление базой знаний остаются доступны только `super_admin`. Ограничение проверяется сервером, а не только скрытием пункта меню.
- Доступ к чату настраивается отдельно для каждой роли: `admin`, `operator`, `viewer`, `supplier`; `super_admin` включён всегда.
- Текущее значение `doxi_settings.allowed_roles` в вашей БД — `["super_admin"]`. После публикации патча другие роли автоматически не включатся. Чтобы включить роль, войдите как `super_admin` в управление Докси, отметьте нужную роль и нажмите «Сохранить настройки».
- Поставщик видит аналитику только по собственным записям. Для остальных ролей остаётся агрегированная аналитика; подробные строки бронирований сохраняются только за `super_admin`.
- Создание/изменение/удаление записей остаются под серверными проверками и отдельным подтверждением. Поставщик ограничен собственными записями; `viewer` не получает право менять записи. Действующие SQL-триггеры и правила бронирования не меняются.
- Блоки рабочих заметок и напоминаний существуют в текущем DockSlot только для `admin` и `super_admin`. Патч включает их управление через существующие таблицы и не создаёт отдельные списки для других ролей. Переключатели `notes_enabled` и `reminders_enabled` действительно выключают соответствующие команды.
- Личная память Докси остаётся отдельной от заметок и напоминаний рабочего стола.
- `upload_registry` доступен только разрешённой и включённой роли и только для соответствующей записи, созданной Докси для того же пользователя.

## Установка

Перед заменой сохраните копии текущих файлов.

### 1. Edge Function

Замените в репозитории файл:

`supabase/functions/doxi-chat/index.ts`

файлом из одноимённого пути этого архива.

Затем опубликуйте функцию штатным способом вашего проекта, например через Supabase CLI:

```bash
supabase functions deploy doxi-chat
```

Не отключайте Verify JWT. Секреты и переменные окружения Edge Function этим патчем не меняются.

**Примечание о версии исходника:** серверный файл собран на основе отдельного исходника `doxi-chat-index-v1_10_3.ts`, который был предоставлен для аудита. Ранее подготовленный edge-патч v1.10.4 содержал жёсткую блокировку всех ролей, кроме `super_admin`; в этом релизе она не используется, поскольку противоречит согласованной multi-role модели. Перед перезаписью production-функции убедитесь, что после присланного исходника в ней не появлялись дополнительные собственные изменения, которые нужно перенести.

### 2. Frontend

Из корня архива репозитория замените файлы в соответствующих путях:

- `js/ai-ds.js`
- `js/ai-ds-management.js`
- все HTML-файлы, находящиеся в `app/` внутри этого архива

HTML-файлы включены для обновления версии подключаемого общего виджета, чтобы пользователям не показывался закэшированный старый `ai-ds.js`.

После замены опубликуйте frontend штатным способом проекта.

### 3. Включение ролей

После публикации Edge Function и frontend войдите под `super_admin`, откройте «Управление Докси», выберите роли, которым нужен чат, и сохраните настройки. По умолчанию текущий список в БД не расширяется автоматически.

Для первого включения рекомендую активировать роли поэтапно и проверить каждую роль отдельной тестовой учётной записью. В частности, проверить:

- `supplier` — только собственные записи и собственная аналитика;
- `viewer` — чтение/агрегаты без операций с бронированиями;
- `operator` и `admin` — только полномочия, которые уже разрешены DockSlot и настройками Докси;
- `admin` и `super_admin` — заметки и напоминания только в собственных блоках «Рабочего стола».

## Изменения БД

**SQL-миграций в этом патче нет.** Не нужно менять RLS, GRANT, функции, триггеры, политики Storage или таблицы: необходимые колонки уже присутствуют по результатам вашего аудита.

Отдельно остаётся диагностический вопрос по тексту `doxi_commit_booking_action`: в присланной копии определения отображалась JSONB-строка с удвоенными кавычками. Файл `diagnostics/READ_ONLY_check_doxi_commit_booking_action.sql` проверяет реальный текст функции. Его можно выполнить в Supabase SQL Editor; он ничего не обновляет. Если `has_doubled_quotes = true`, пришлите результат до изменения SQL-функции — в этот релиз она намеренно не включена.
