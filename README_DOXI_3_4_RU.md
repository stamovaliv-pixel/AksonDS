# AKSON DockSlot — Doxi 3.4.0

Единый релиз Doxi 3.4: Cognitive Core, контролируемая маршрутизация инструментов, улучшенное извлечение знаний и памяти, многоэтапный анализ с проверкой, веб-поиск и существующие операции DockSlot.

## 1. Что входит в релиз

### Cognitive Core
- Восстановление высокоуверенных ошибок русской/английской раскладки и ограниченного набора очевидных опечаток до обработки запроса. Исходный текст в истории не переписывается.
- Планировщик запускается только для явно многоэтапных аналитических запросов. Он возвращает структурированный JSON-план: сложность, разрешённые read-only источники, термины поиска и уточнение с порогом уверенности.
- Низкая уверенность не блокирует ответ и не заставляет пользователя переформулировать обычный запрос.

### Agent Tools
- Планировщик может запросить только `knowledge_lookup` и `live_data_lookup`.
- Фактическое чтение выполняется серверными функциями текущего DockSlot, а не моделью напрямую.
- Создание/изменение/удаление бронирований остаётся в существующих защищённых обработчиках, с проверкой роли, ограничений и отдельным подтверждением.
- Заметки, напоминания, память и анализ вложений проходят существующие серверные обработчики. Это не произвольное выполнение команд моделью.

### Knowledge & Memory
- Сохранены корпоративная база знаний, персональная память пользователя, краткое резюме длинных диалогов и история текущего пользователя.
- Планировщик расширяет поисковый запрос связанными терминами. Поиск в текущей версии — расширенный лексический/ключевой поиск, а не векторный pgvector RAG; миграций для embeddings в этом релизе нет.
- Персональная память остаётся изолированной по `auth.uid`.

### Reasoning Engine
- Для многоэтапной аналитики модель получает структурированный план и усиленную инструкцию разложить задачу на этапы, отдельно проверять числа, единицы, допущения и гипотезы.
- Сложный ответ проходит второй проверочный проход локальной моделью. Поле `answer_verified` показывает, вернул ли проверяющий ответ; это не математическое доказательство и не гарантия абсолютной безошибочности.
- Исходные данные и ограничения должны быть явно отражены в выводе.

### Model Intelligence
- В синхронном пути используется проверенная локальная `qwen3.5:9b`.
- `qwen3:14b` не включена в автоматическую маршрутизацию: в ранее измеренном окружении пользователя она формировала ответ примерно 9 минут, тогда как Supabase имеет 150 секунд request idle timeout. Такой маршрут обрывал бы реальные запросы.
- «Глубокий режим» в Doxi 3.4 — это ограниченный многоэтапный проход на той же модели 9B, а не незаметное переключение на 14B.
- Для обычных вопросов планировщик не вызывается, чтобы не увеличивать очередь для шести сотрудников.

### Web Search
- `/интернет запрос` и фраза «найди в интернете …» доступны только `super_admin`.
- Используется Brave LLM Context API. Внешнему поисковику отправляется только отдельная публичная поисковая фраза; история, память, имя пользователя, данные DockSlot и файлы не передаются.
- Фрагменты страниц считаются недоверенными данными. Докси возвращает HTTPS-источники отдельным блоком.
- Для функции нужен серверный secret `BRAVE_SEARCH_API_KEY`. Без него обычный чат продолжает работать, поиск вернёт понятное сообщение о настройке.

### Сохранённые функции
- MultiRole и серверные проверки роли;
- CSV/XLS/XLSX анализ через `node-xlsx@0.25.0`;
- история, резюме и персональная память;
- база знаний;
- live read-only данные DockSlot с ограничением доступа поставщика к своим записям;
- личные заметки и напоминания, включая разбор «с текстом …» и отказ для времени в прошлом;
- карточки подтверждения и отдельный commit для записей;
- управление настройками и комментариями ожидания Докси.

## 2. Состав пакета

- `supabase/functions/doxi-chat/index.ts` — единственный файл Edge Function. Дополнительный `input-understanding.ts` не требуется.
- `ollama/ollama-proxy-6workers-v34.ps1` — обновлённый loopback-only proxy для JSON-режима планировщика, шести пользователей и очереди Ollama.
- `js/ai-ds.js` и `css/ai-ds.css` — frontend Докси, команда веб-поиска и отображение источников.
- `app/*.html` — 14 страниц с обновлёнными cache-busting версиями AI CSS/JS.
- `diagnostics/DOXI_3_4_ACCEPTANCE_RU.md` — приёмочные тесты.

## 3. Установка — безопасный порядок

### Шаг A. Резервные копии
1. В Supabase → Edge Functions → `doxi-chat` → Code нажмите Download и сохраните текущую функцию.
2. В GitHub/локальном проекте сохраните копии `js/ai-ds.js`, `css/ai-ds.css` и 14 HTML-страниц из `app/`.
3. На компьютере сохраните копию текущего активного proxy script.

### Шаг B. Обновить локальный Ollama proxy
1. Убедитесь, что модель `qwen3.5:9b` доступна в Ollama.
2. Остановите только текущее окно PowerShell с proxy через `Ctrl+C`. Cloudflare Tunnel не останавливайте.
3. Скопируйте `ollama/ollama-proxy-6workers-v34.ps1` в `C:\cloudflared\ollama-proxy-6workers-v34.ps1`.
4. Запустите отдельным окном PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\cloudflared\ollama-proxy-6workers-v34.ps1"
```

5. Оставьте окно открытым. В другом окне PowerShell проверьте:

```powershell
$secret = (Get-Content -LiteralPath "C:\cloudflared\secret.txt" -Raw).Trim()
Invoke-RestMethod -Uri "http://127.0.0.1:8787/health" -Method Get -Headers @{ "X-Akson-Secret" = $secret } | Format-List
$secret = $null
```

Ожидается `ok : True` и `base_model : True`. Proxy принимает только `qwen3.5:9b`, ограничивает параметры Ollama и поддерживает `format=json` для планировщика. Он остаётся привязанным к `127.0.0.1` и требует прежний shared secret.

### Шаг C. Обновить Edge Function через Supabase Dashboard
1. Supabase Dashboard → проект DockSlot → Edge Functions → `doxi-chat` → Code.
2. В FILES выберите только `index.ts`.
3. Откройте файл из архива `supabase/functions/doxi-chat/index.ts`, скопируйте весь текст и замените содержимое редактора Supabase (`Ctrl+A`, затем `Ctrl+V`).
4. В FILES должен остаться один `index.ts`. Не нажимайте Add File: импортируемого `input-understanding.ts` в 3.4 нет.
5. Нажмите Deploy updates и дождитесь `Successfully updated edge function`.
6. `Verify JWT` должен оставаться включённым.

SQL Editor не нужен; миграций и изменений RLS в 3.4 нет.

### Шаг D. Настроить Web Search (необязательно)
1. Создайте/получите Brave Search API key в кабинете Brave.
2. В Supabase → Project Settings → Edge Functions → Secrets (название раздела может отображаться как Edge Function Secrets) добавьте `BRAVE_SEARCH_API_KEY` со значением ключа.
3. Не помещайте ключ в HTML, JS, GitHub или сообщения Докси. Удаление этого секрета отключает веб-поиск.
4. Без этого секрета остальные возможности Doxi 3.4 работают, а поиск сообщает, что не настроен.

### Шаг E. Обновить frontend
Из папки релиза перенесите в GitHub-репозиторий DockSlot с сохранением путей:
- `js/ai-ds.js`;
- `css/ai-ds.css`;
- все 14 файлов `app/*.html`.

Сделайте commit и опубликуйте frontend привычным способом проекта (RelaxDev/Vercel). В HTML обновлены версии кэша CSS/JS. Backend в Supabase не заменяет статический frontend.

## 4. Первый запуск и ограничения

- Не включайте в Ollama другие модели для Doxi одновременно; `OLLAMA_NUM_PARALLEL=2`, `OLLAMA_MAX_QUEUE=32` и текущая очередь сохраняются.
- Не запускайте два proxy на одном порту 8787.
- Не закрывайте окно нового proxy после запуска.
- Не используйте `--no-verify-jwt`, не меняйте роли и RLS.
- Web Search изолирован: не передавайте в поисковую строку внутренние номера, ИНН, телефоны, email, UUID, ВзУ, сведения о поставщиках или коммерческие значения.
- Это статически проверенный пакет. Реальный bundle/deploy в вашем проекте, работу Brave с вашим ключом и живой Ollama после обновления proxy нужно подтвердить приёмочными тестами.

## 5. Откат
- Edge Function: откройте резервную копию `index.ts` и повторно опубликуйте её через Deploy updates.
- Frontend: верните резервные версии `js/ai-ds.js`, `css/ai-ds.css` и `app/*.html` и опубликуйте штатно.
- Proxy: остановите окно 3.4 через `Ctrl+C` и запустите сохранённую резервную версию предыдущего `ollama-proxy-6workers.ps1`.
- Cloudflare Tunnel и Ollama настройки при откате менять не нужно.
