# DockSlot Messenger v1.10 — инструкция по установке

Патч v1.10 собран поверх DockSlot Messenger v1.9. ZIP содержит только изменённые файлы проекта.

## Что входит в патч

- `js/chat.js` — получение имён из `profiles.company_name`, сценарий «Обсудить запись», выбор адресатов и групп, переход к уже связанному сообщению, ускоренное обновление списка, принудительная прокрутка вниз при новом сообщении в открытом диалоге и менее затратное изменение высоты поля ввода.
- `css/chat.css` — положение плавающей кнопки по образцу отмеченной области, плавнее градиент, усиленная подсветка, минимальная ширина сообщений, вынесенные за край карточки действия и реакция, выравнивание активных реакций справа, оформление всплывающего действия по записи.
- `app/*.html` — обновлены только cache-busting версии `chat.css` и `chat.js` до `20261125-messenger-v1-10`.
- `supabase/migrations/20261125_dockslot_chat_booking_discussions.sql` — защищённая RPC-функция создания обсуждения записи.

## Порядок установки

1. Сохраните резервные копии перечисленных в ZIP файлов.
2. В Supabase Dashboard откройте SQL Editor и выполните `supabase/migrations/20261125_dockslot_chat_booking_discussions.sql`.
3. Дождитесь успешного завершения SQL без ошибок.
4. Распакуйте ZIP поверх корня проекта `AksonDS-main`, сохраняя структуру папок.
5. Опубликуйте фронтенд через RelaxDev.
6. Обновите страницы браузера через Ctrl+F5.

Старые миграции Messenger повторно выполнять не нужно. Edge Function повторно публиковать не нужно. Новая SQL-функция вызывается из браузера с пользовательской сессией; проверка получателей и роли выполняется на стороне базы данных.

## Проверка сценария «Обсудить запись»

1. Войдите под `admin` или `operator` и откройте страницу дня.
2. Найдите свободную/не связанную с вашей перепиской запись и нажмите серую пиктограмму сообщения.
3. Выберите «Обсудить запись».
4. Проверьте список сотрудников: доступны только роли `admin` и `operator`.
5. Проверьте быстрые группы «УТЗ», «РЦ» и «Всем».
6. Выберите получателя или группу и начните переписку.
7. Отправьте первое сообщение и проверьте, что оно связано с выбранной записью.
8. Повторите сценарий с двумя аккаунтами и убедитесь, что чужое личное сообщение не активирует пиктограмму для постороннего сотрудника.

## Поведение и ограничения

- Личные адресаты сценария записи ограничены ролями `admin` и `operator`; поставщики не участвуют.
- Группа «Всем» для обсуждения записи включает сотрудников `admin` и `operator`, которым суперадминистратор разрешил мессенджер. Отправитель не добавляется как собственный адресат.
- Группы «УТЗ» и «РЦ» выбирают соответственно `admin` и `operator`.
- Новая переписка может быть создана до отправки первого текста; `booking_id` передаётся с первым сообщением из выбранного чата.
- Существующая схема отправки через Supabase RPC и обновления через Realtime сохранена. Переход на другой транспорт не выполнялся.
- Автопрокрутка срабатывает при открытии переписки, собственной отправке, Realtime INSERT в активную переписку и при обнаружении нового последнего сообщения резервным обновлением.

## Проверки перед публикацией

Проверены синтаксис `js/chat.js`, баланс CSS-блоков, наличие ресурсов и ссылки на версии v1.10 во всех изменённых HTML-страницах, целостность ZIP. Фактический SQL-запуск, браузерная проверка и проверка нескольких ролей в вашей Supabase-среде не выполнялись.
