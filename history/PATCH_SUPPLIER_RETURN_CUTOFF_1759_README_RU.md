# DockSlot — ограничение «Возврат» на завтра до 17:59 МСК

Патч изменяет только правило для поставщика, который создаёт запись на завтра с типом поставки `return` или добавляет `return` к уже существующей записи на завтра.

## Новое правило

- До 17:59:59 включительно по времени `Europe/Moscow` действие разрешено.
- Начиная с 18:00:00 по Москве действие запрещено.
- Ограничение действует только на дату слота, равную завтрашнему календарному дню по Москве.
- При редактировании уже существующей записи, где `return` был выбран ранее, другие изменения после 18:00 не блокируются.
- Ограничение применяется к роли `supplier`. Роли администратора и оператора не затрагиваются.
- Все прежние проверки и параметр `app_settings.return_deadline_days` сохраняются без изменений.

## Состав ZIP

- `js/day.js` — клиентская проверка и понятное сообщение до отправки формы.
- `app/day.html` — обновлён query-параметр `day.js`, чтобы браузер загрузил новую версию скрипта.
- `supabase/migrations/20261125_supplier_return_tomorrow_cutoff_1759.sql` — серверная проверка на INSERT и UPDATE; обход клиентской проверки невозможен.
- Этот README, changelog и SHA256-манифест.

## Установка через веб-интерфейс

1. Сделайте резервные копии заменяемых файлов.
2. В Supabase Dashboard откройте SQL Editor и выполните файл миграции `20261125_supplier_return_tomorrow_cutoff_1759.sql`.
3. Распакуйте `js/day.js` и `app/day.html` поверх проекта, сохраняя структуру каталогов.
4. Опубликуйте обновлённые файлы через RelaxDev.
5. Обновите страницу поставщика через Ctrl+F5.

CLI и Edge Functions не требуются. Полная миграция `security_hardening_v4_1.sql` повторно не запускается.

## Проверка

Проверьте четыре сценария:

1. Сегодня до 18:00 МСК: поставщик создаёт слот на завтра с `return` — разрешено.
2. Сегодня с 18:00 МСК: поставщик создаёт слот на завтра с `return` — отказ.
3. Сегодня с 18:00 МСК: поставщик добавляет `return` к существующему слоту на завтра — отказ.
4. После 18:00 МСК: поставщик редактирует комментарий у записи, где `return` уже был выбран до дедлайна, — это новое ограничение не блокирует.

Серверный триггер является окончательной проверкой. Клиентская проверка нужна для удобного сообщения, но не заменяет серверную защиту.
