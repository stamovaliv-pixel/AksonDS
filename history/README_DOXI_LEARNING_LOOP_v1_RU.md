# DockSlot / Докси — «Опыт и обучение» v1.0

Версия Edge Function: **3.4.11**

## Что добавлено

1. **Автоматический журнал затруднений.** После обычного ответа Докси Edge Function проверяет, содержит ли ответ явные признаки нехватки данных/знаний, недоступности данных или ограничения прав. Такие случаи попадают в `public.doxi_learning_cases`.
2. **Ручное добавление.** На странице «Управление Докси» Super Admin может добавить вопрос вручную — это полезно, когда Докси дала уверенный, но неверный ответ и автоматический детектор его не распознал.
3. **Выгрузка журнала CSV.** CSV открывается в Excel. В выгрузку не входят внутренние UUID пользователя, диалога и сообщения.
4. **JSON-шаблон решений.** Кнопка формирует шаблон из ожидающих разбора случаев. Сохраняется `case_id`; его нельзя менять. В одном шаблоне до 100 вопросов.
5. **Загрузка проверенных решений.** Edge Function проверяет структуру, категории и совпадение `case_id`, затем создаёт карточки в существующей `doxi_knowledge_documents`. Статус вопроса становится `trained`.
6. **Прогресс.** На панели показываются число зафиксированных вопросов, очередь разбора, количество обученных вопросов и число типов контекста, для которых уже загружены проверенные решения.
7. **Сворачиваемые разделы.** Настройки, матрица доступа, подключение, личность, границы, база знаний, опыт, комментарии и память свёрнуты в компактные панели. Все существующие ID элементов сохранены.

## Важно понимать, что значит «обучение»

Это не fine-tuning и не изменение весов Qwen 3.5:9B. Проверенные решения добавляются в существующую базу знаний и подбираются как контекст при последующих похожих запросах. Поэтому прогресс отражает количество проверенных случаев, добавленных в базу знаний, и количество покрытых типов контекста, а не процент переобучения модели.

Автоматический журнал фиксирует только ответы с явными сигналами неопределённости/ошибки. Уверенный, но неверный ответ может не попасть в него автоматически — для этого предусмотрено ручное добавление вопроса в том же разделе.

## Порядок установки

### 1. Применить SQL

В Supabase → SQL Editor выполните **один раз** файл:

`supabase/migrations/20261118_doxi_learning_loop.sql`

Миграция создаёт `public.doxi_learning_cases`, включает RLS и отзывает права у `anon` и `authenticated`. Выдаёт CRUD только `service_role`.

Таблица намеренно **не добавляется** в матрицу `doxi_table_permissions`: чат-модель не должна напрямую читать журнал. Доступ к журналу реализован отдельными действиями Edge Function, которые доступны только `super_admin`.

### 2. Развернуть Edge Function

Supabase → Edge Functions → `doxi-chat`:

- полностью замените `index.ts` файлом из патча;
- нажмите Deploy updates;
- оставьте `Verify JWT` включённым.

Никакие Secrets, URL туннеля, Proxy, Ollama или модель менять не нужно.

### 3. Опубликовать интерфейс

В GitHub замените по тем же путям:

- `app/ai_ds_management.html`
- `css/ai-ds-management.css`
- `js/ai-ds-management.js`

Опубликуйте RelaxDev/Vercel и откройте страницу управления Докси с `Ctrl + F5`.

## Рабочий процесс

1. В «Управление Докси» раскройте панель **«Опыт и обучение Докси»**.
2. Смотрите очередь автоматически зафиксированных случаев. Ненужные случаи можно отправить в архив.
3. Нажмите **«Скачать шаблон решений JSON»**. В нём будут ожидающие вопросы с исходными формулировками, ответами Докси, причиной и неизменяемым `case_id`.
4. Заполните для тех вопросов, которые разобрали:
   - `title` — короткое название карточки;
   - `category` — `general`, `company`, `project`, `roles`, `communication`, `processes`, `glossary` или `faq`;
   - `context_type` — `general`, `bookings`, `suppliers`, `arrivals`, `verification`, `calendar`, `permissions` или `warehouse`;
   - `questions` — исходный вопрос и варианты его формулировки;
   - `content` — проверенное правило/ответ с оговорками и условиями применения (от 30 до 12 000 символов).
5. Загрузите заполненный JSON. Один файл — до 100 решений и 2 МБ.
6. Докси сохранит их в базу знаний. Повторная загрузка того же файла не создаёт дубликаты.

Для обработки следующей партии вопросов скачайте новый шаблон — уже обученные случаи из очереди исчезнут.

### Пример структуры JSON

```json
{
  "schema_version": "doxi-learning-solutions-v1",
  "solutions": [
    {
      "case_id": "UUID из скачанного шаблона — не менять",
      "title": "Проверка фактического прибытия поставщика",
      "category": "faq",
      "context_type": "arrivals",
      "questions": [
        "Приезжал ли поставщик 18.11?",
        "Есть ли отметка о прибытии у поставщика за эту дату?"
      ],
      "content": "Проверенное правило: ... Условия: ... Источник актуальных данных: ..."
    }
  ]
}
```

В реальном файле вместо поясняющего текста в `case_id` должен находиться UUID из скачанного шаблона.

## Ограничения и безопасность

- Журнал и его административные действия доступны только `super_admin`.
- Браузер не получает прямых прав на таблицу журнала; используется защищённая Edge Function с service role.
- В журнале сохраняются вопрос, ответ Докси, роль пользователя, раздел и тип затруднения. Email, телефон и длинные 10–12-значные номера перед сохранением маскируются.
- CSV-выгрузка не содержит UUID пользователя/диалога/сообщения.
- Загружается только проверенный `content`; файл не может менять системные инструкции, полномочия, SQL, RLS или действия DockSlot.
- Решения импортируются в `doxi_knowledge_documents` только при разрешённом `can_insert`. Обновление/удаление документов через импорт не выполняется. Если карточку нужно заменить, удалите старый материал с источником `doxi-learning:<case_id>` в списке базы знаний и повторите импорт.
- Модель может ошибиться уверенно. Поэтому ручное добавление вопроса обязательно оставлено.
- Текущий лимит общей базы знаний — 100 документов; SQL/код не увеличивает его автоматически.

## Проверка после установки

1. Откройте управление Докси. Панель «Опыт и обучение» должна показывать нули, если журнал пуст.
2. Добавьте вопрос вручную и проверьте счётчики/CSV/JSON-шаблон.
3. Заполните шаблон решением длиной не менее 30 символов и импортируйте.
4. Убедитесь, что счётчик «Обучено вопросов» увеличился, а число освоенных типов контекста обновилось.
5. Задайте Докси тот же вопрос и близкую по смыслу формулировку. Проверенное решение должно попасть в контекст ответа; актуальные цифры и записи всё равно должны проверяться запросом к БД.
6. Повторно загрузите тот же JSON: дубликатов в базе знаний быть не должно.

Живое подключение к рабочему Supabase и браузерная проверка после деплоя не выполнялись при подготовке патча.
