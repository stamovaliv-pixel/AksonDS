# DockSlot — исправление фоновой загрузки уведомлений

## Что исправлено

Изменён только клиентский модуль уведомлений и cache-buster его подключения на страницах приложения.

- Перед каждым чтением `public.app_notifications` проверяется актуальная сессия Supabase.
- Проверяется, что `session.user.id` совпадает с пользователем, для которого открыт центр уведомлений.
- При отсутствии сессии запрос не отправляется; резервный опрос останавливается.
- При PostgreSQL `42501` или HTTP `401/403` резервный опрос приостанавливается, чтобы не создавать повторяющийся поток ошибок. Повтор допускается после `SIGNED_IN` или `TOKEN_REFRESHED`.
- При `SIGNED_OUT` останавливаются таймер и Realtime-подписка, а пользовательское состояние центра уведомлений очищается.
- После обновления токена проверка восстанавливается; Realtime остаётся основным каналом доставки.
- Резервный опрос при сбое Realtime сохранён с прежним интервалом 30 секунд, но не выполняется в скрытой вкладке. При возврате вкладки в видимое состояние выполняется обновление.
- Одновременные запросы списка уведомлений объединяются, чтобы не создавать параллельные одинаковые SELECT.

## Что не менялось

- Таблицы `app_notifications`, `notification_preferences`, `push_subscriptions`.
- GRANT, RLS и политики Supabase.
- Database Webhooks, Edge Functions, Web Push и Service Worker.
- Состав событий, фильтры по `user_id`, отображение уведомлений, настройки и действия пользователя.
- Realtime-подписка на INSERT/UPDATE и резервный интервал 30 секунд.

SQL-миграция не требуется. Не выдавайте `SELECT` роли `anon`.

## Файлы

Заменить `AksonDS-main/js/notifications.js`.

Также заменить 12 HTML-страниц из `AksonDS-main/app/` из этого патча: у них обновлён параметр версии `notifications.js`, чтобы браузер загрузил новый скрипт, а не старый файл из кэша.

## Установка

1. Сохраните копии текущих `js/notifications.js` и HTML-файлов из архива.
2. Замените файлы из патча по тем же путям в GitHub.
3. Опубликуйте изменения.
4. Откройте DockSlot и выполните `Ctrl+F5`.
5. Проверьте вход, центр уведомлений, получение нового уведомления через Realtime, а также выход из системы в другой вкладке.

## Ожидаемое поведение

- При рабочем Realtime уведомления поступают мгновенно, резервный опрос не работает.
- При временном сбое Realtime и действующей сессии список обновляется не реже чем раз в 30 секунд.
- После выхода из системы или потери сессии новые запросы к `app_notifications` не отправляются.
- При ошибке авторизации/прав `42501`, `401` или `403` повторные запросы не продолжаются бесконечно; повтор разрешается после новой авторизации или обновления токена.
