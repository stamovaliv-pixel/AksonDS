# Заметки по развёртыванию — «Аксон ДокСлот» v4.1

В этой папке оставлен один SQL-файл для исходного внедрения:

- `security_hardening_v4_1.sql` — полный пакет безопасности и функций v4.1. Для ситуации пользователя, где v3/v4 не применялись, его выполняют один раз после резервного копирования и проверки схемы.

Старые дублирующий SQL и инкрементальный patch удалены из финального архива. Не ищите и не запускайте альтернативные файлы из старых архивов `v2`, `v3` или `v4` поверх этого комплекта.

## Перед запуском

- Создайте и проверьте резервную копию PostgreSQL; отдельно сохраните объекты Storage bucket `registries`.
- Проверьте RLS, текущие политики, триггеры, функции и соответствие колонок — см. `../SECURITY_README.md`.
- Во время применения запретите пользователям менять бронирования.
- Перед SQL в Dashboard → Storage → `registries` отключите `Public bucket` (bucket должен стать Private); SQL отдельно проверит это условие. Учитывайте, что текущий сайт, пока он использует публичные URL, может временно не открывать реестры.
- Выполните `security_hardening_v4_1.sql` один раз в SQL Editor Supabase.
- Если появилась ошибка, не публикуйте сайт и не повторяйте запуск без анализа причины.

SQL обновляет политики пяти таблиц, серверную валидацию бронирований, обработчик регистрации и правила Storage. Bucket `registries` необходимо сделать приватным через Dashboard до запуска SQL: миграция не пытается изменять управляемую таблицу `storage.objects` или напрямую менять настройки bucket из SQL. Также добавляется календарь исключённых дат с очисткой просроченных значений.

Миграция не выполнялась против рабочей базы из комплекта. После применения выполните приёмочные тесты для каждой роли, даты-исключения, замены реестра, времени убытия и скачивания файлов через signed URL.
